# Brexit ML Engine (Phase 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a local Python service that trains XGBoost surrogates on 228 AnyLogic runs and exposes Raw (`/predict`) and Semantic (`/scenario/predict`) APIs, with Semantic v1 limited to IRE↔GB direct corridor scenarios per the approved freeze.

**Architecture:** Single package `brexit_ml/` at the project root: Excel → Parquet (`data_loader`), offline training with registry (`train`), inference with scaler + optional zero-inflation classifiers (`ml_engine`), FastAPI raw routes (`ml_api`), facade that translates seven semantic fields to 153 raw inputs and filters outputs (`param_translator`, `output_filter`, `corridor_router`, `semantic_api`). Phase 2 enum values may exist in schemas but unsupported semantic combinations return HTTP 400 until explicitly enabled.

**Tech Stack:** Python ≥3.10, XGBoost, scikit-learn, pandas, NumPy, PyArrow, OpenPyXL, FastAPI, Uvicorn, Pydantic v2, Joblib, pytest, httpx (optional for API tests).

**Authoritative spec:** `docs/ml/spec/brexit_ml_engine_spec.md`

**V1 freeze (normative for this plan):**
- Semantic `POST /scenario/predict` accepts only journeys listed in spec Section 19 (`route_type` must be `direct_gb`, matrix as in the table). Any other combination → **400** with `error: "invalid_input"` and `detail` mentioning unsupported Phase 1 scenario.
- `_infer_ire_port` for resources: on **import**, apply `customs_officers` / `dafm_officers` / `security_officers` / `tractors` to the Irish port (`dublin` or `rosslare` from the request). On **export**, when `origin_port` is Irish, use that port for resources.
- Phase 2 raw outputs remain `not_trained` in responses until new data and retrain; no requirement to implement EU semantic translation in v1.
